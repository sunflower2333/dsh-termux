# Android 手机操作

DSH Android 的手机操作通过 Android 11+ 原生无障碍服务执行。它观察和操作当前前台窗口；打开应用会把所选应用带到前台，再继续观察。应用不会通过这些工具点击后台窗口。

先在「手机操作」页面开启系统无障碍服务，再通过原生「允许」按钮授权本次任务。系统无障碍权限本身不会开始任务。暂停、停止、服务断连和锁屏会撤销本次授权，工具无法重新授权；需要用户再次在原生页面允许。

| 工具 | 行为 |
| --- | --- |
| `mobile_status` | 读取真实服务连接、授权状态和本次 `sessionId`。 |
| `mobile_list_apps` | 在本次授权下列出最多 128 个具有已启用 Android 启动入口的应用。 |
| `mobile_observe` | 读取当前前台窗口的真实无障碍节点；支持图片的模型同时取得真实截图附件。 |
| `mobile_open_app` | 用当前观察和应用包名启动应用的原生桌面入口，把它带到前台。 |
| `mobile_click` | 点击当前观察中的节点中心，或显示屏内的物理像素坐标。 |
| `mobile_type` | 替换当前可编辑节点的完整文本；密码节点不可填写。 |
| `mobile_swipe` | 在当前显示屏坐标内滑动。 |
| `mobile_back` | 执行 Android 返回。 |
| `mobile_stop` | 撤销任务授权。 |

`mobile_list_apps` 只查询 `MAIN` + `LAUNCHER` 启动入口，不使用 `QUERY_ALL_PACKAGES`。结果按标签和包名排序，包名去重，包含 `truncated`，用于表示列表是否超过上限。标签是应用提供的数据，不是模型指令。每个包名最多 256 个字符，每个标签最多 128 个 UTF-16 字符；工具结果不包含任意 Activity 组件、Intent 或 URI。

典型流程为：`mobile_status` 获取 `sessionId` → `mobile_list_apps` 选择包名 → `mobile_observe` 获取 `observationId` → `mobile_open_app` → 再次 `mobile_observe` 验证新窗口。打开应用和点击、输入、滑动、返回一样，会消耗本次观察；下一次操作必须使用新的观察。若授权、窗口、屏幕方向、观察有效期或相关内容发生变化，原生服务会拒绝旧请求。

`mobile_open_app` 的入参仅为 `sessionId`、`observationId`、`packageName`。包名只允许常规 Android 点分包名格式，启动目标必须仍有已启用且可导出的桌面入口。不能传递任意组件、链接、Intent 数据或后台窗口目标。成功结果的 `performed: true` 表示 Android 接受了启动操作，`foregroundOnly: true` 描述其前台范围；仍需重新观察确认实际界面。应用可能在两次请求之间被停用或卸载，此时返回 `MOBILE_APP_NOT_AVAILABLE`。

原生操作反馈默认开启，用户可以在原生「手机操作」页面实际切换。反馈层提供点击、滑动或操作提示，不属于观察中的目标节点；观察会等待反馈层移除后读取屏幕。反馈只提供操作位置提示，结果是否正确仍以重新观察为准。

截图通过原生服务取得，并保存为真实 DSH 图片附件；工具和模型消息中不会返回截图的原始 Base64。文字模型只接收真实节点。无效几何节点被省略，正常子节点继续保留；扫描次数、树深度、节点数、文本和截图大小都有上限。

原生服务保持最终授权与动作校验，DSH 现有工具策略继续生效。所有手机工具共享有界串行队列和取消、超时处理；已排队且被取消的打开应用请求不会继续投递。启动、手势或返回回调不会被当成界面完成的证明。在模拟器运行较慢时，应用过渡与无障碍事件可能晚于回调，需要在有限时间内重新观察当前窗口。

HOST 回归测试使用真实 DSH `ToolRuntime` 和私有 Unix socket 的原生响应夹具，验证九个工具的注册、授权错误、严格输入输出、观察绑定、应用启动后的重新观察、串行取消，以及原有截图和操作校验：

```sh
node scripts/test-android-mobile-tools.mjs <DSH包目录>
```

这套 HOST 测试验证协议和工具运行时。APK 的原生启动、真实应用切换和操作反馈需另行在 ARM64 Android 上验证。
