# Android 工作区

新安装默认使用应用私有目录：

```text
<应用数据目录>/files/Documents/deepseek-harness/default-workspace
```

界面根据语言显示“默认工作区”，实际目录名不会随语言更改。
现有工作区、会话和文件保持原路径，升级不会把它们迁移到这个默认目录。
默认工作区只在工作区登记和会话历史都为空时自动建立。

“添加工作区”的目录浏览从应用的 `files/Documents` 开始，避免从存放配置的 `dsh-home` 开始。
原有目录浏览、创建子目录和选择确认由 DSH 的真实文件系统后端处理。
原生启动器提供 Documents 路径、应用数据根目录和 UID；默认解析检查规范化后的路径位于该根目录内，目录真实存在、归应用 UID 所有，且 Documents 本身不是符号链接。
缺少或无效的默认路径会返回错误，不改用文件系统根目录、系统目录、下载目录或运行时 HOME。

选择另一工作区会打开或复用该工作区自己的会话，新会话的 `cwd` 使用该工作区的规范化路径。
已有会话的 `cwd` 不会因为另选工作区而更改。
取消目录选择只关闭选择界面；浏览或创建失败不会选择一个替代工作区。
工作区登记在 DSH 的持久存储中保存，当前会话选择仍由已有的 Web UI 状态恢复。

当前工作区后端接受普通绝对文件路径，并受 Android 应用文件访问权限限制。
添加工作区提供两个 DSH WebUI 选项：使用应用内目录，无需存储授权；选择手机文件夹，打开 Android 系统目录选择器。说明、按钮及错误信息跟随 DSH 当前语言与主题，没有独立的原生设置页面。

Android 11+ 的共享存储工作区使用“所有文件访问权限”。只有用户选择手机文件夹后才跳转到本应用的系统授权页；返回后重新检查实际权限，再打开 `ACTION_OPEN_DOCUMENT_TREE`。拒绝授权、取消选择或目录不可用时，原会话、草稿和工作区保持。

系统选择器仅支持本地 ExternalStorageProvider 的主存储或系统已挂载的可移动卷。通过真实卷目录解析选择结果，检查规范路径仍在该卷内，并验证临时文件写入、读回和删除；后端再次检查真实目录后才登记。卷根、路径穿越、Android/data、Android/obb、越界符号链接、只读目录以及无法映射的提供者会被拒绝，错误显示在 DSH WebUI。

单文件夹 SAF 的持久 URI 授权不能让 Node/Bash 直接读写对应 POSIX 路径，因此本版共享工作区需要所有文件访问权限，不声称已实现仅授予单文件夹的实时工作区或云盘工作区。文件附件导入和配置文件编辑仍使用各自的系统选择器。系统存储授权不会改动 DSH 的文件策略或命令审批。
文件工具的工作区写入限制与 Bash 单次审批继续遵循 [SANDBOX.md](SANDBOX.md)。

新文件在支持的文件系统上使用原子、禁止覆盖的重命名。部分 Android 共享存储不支持该标志，此时先排他创建目标，再写入并核对内容；不会覆盖并发创建的文件，也不会修改文件策略。此回退的内容在写完前可能被其他进程看到。取消、I/O 错误或崩溃可能留下部分文件，需要先读取再修复；应用不会为清理失败写入而删除公开目标。已有文件的版本检查、编辑和替换路径保持。

## HOST 验证

```bash
node scripts/test-android-workspace.mjs /path/to/dsh-package
```

测试直接使用实际的默认目录解析、目录浏览、JSON 持久存储和工作区登记服务。
会话创建使用实际 `SessionCommandController`，其 Agent 接纳端是有界 fixture。
测试覆盖 Documents 初始位置、子目录创建、无效默认无回退、URI 拒绝、工作区重新打开仍保留 ID/路径、新会话的工作区 `cwd` 和旧会话的 `cwd` 保持。
HOST 结果不能证明 Android 上已经点击并验证选择器界面。

## ARM64 验证步骤

1. 保留现有会话，记录所选会话 ID、草稿、工作区路径和当前进程；不要清除应用数据。
2. 打开工作区菜单 → 添加工作区。确认初始路径为应用 `files/Documents`，页面全屏且系统栏、返回键和底部选择按钮可用。
3. 在 Documents 中建立仅用于测试的 `qa-workspace-<唯一名称>` 子目录，进入后确认选择。验证该工作区已登记，新建或复用的会话 `cwd` 为该子目录的规范化路径。
4. 发起有界命令 `pwd`，通过正常 DSH 单次审批，检查真实输出等于该目录。使用文件工具在这个目录内写入并读回测试文件。
5. 返回原会话，确认原 `cwd` 和草稿仍在。再打开添加工作区并取消或按返回；所选会话 ID、草稿及原路径不变。
6. 再次打开工作区菜单，确认测试工作区登记仍在。正常后台/返回应用后重新选择它，确认会话仍指向该路径。
7. 若需验证主机重启后的持久性，必须由模拟器所有者安排；先确认没有运行中的用户任务，再停止和恢复 DSH。不能用清除数据或伪造路径替代验证。
8. 只清理这一轮拥有的测试文件、工作区登记及测试会话；保留已有工作区、文件和历史。
